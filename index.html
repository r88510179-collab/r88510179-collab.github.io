Case Study

On-Prem to M365 Migration at ~1,000 Users

Professional services environment · 2023 · Key contributor

I contributed to a multi-phase migration from on-prem Active Directory and Exchange to Microsoft 365, running alongside a Cisco to Teams Phone cutover. The work touched every user, every device, and the phone system.

Problem

The firm was operating on aging on-prem infrastructure with growing limits around scale, remote access, and modern authentication. Leadership committed to a full cloud migration covering identity, mail, collaboration, and telephony in one coordinated effort.

Approach

The project broke into overlapping phases: AD audit and inventory, identity sync and MFA rollout, mailbox cutover, device enrollment through Intune, Teams rollout as the new collaboration layer, Cisco phone decommission, and cleanup of stale on-prem objects. Teams doubled as the telephony replacement, which meant the voice cutover had to land on the same schedule as the chat rollout.

What I Owned

  • AD auditing and inventorying across the full user base
  • MFA rollout end to end, including user communication and exception handling
  • Authentication troubleshooting during and after cutover
  • Batch planning and cutover scheduling
  • Outlook profile fixes for users hitting post-migration issues
  • Device enrollment into Intune
  • Teams rollout, including the Cisco phone migration
  • Admin process design in Teams Admin Center and PowerShell
  • Stale AD object cleanup after decommission

Tools

Microsoft Entra (Azure AD) · Intune · Exchange Online · Teams Admin Center · PowerShell (ExchangeOnlineManagement, MicrosoftTeams modules) · on-prem Active Directory

Automation I Built Along the Way

Part of what I owned was standardizing how the admin team connected to Exchange Online and Teams. We were running the same setup steps by hand every time someone spun up a new PowerShell session. I wrote a helper module that handles module installation, connection functions for EXO and Teams, and optional drive mapping, all inside a managed block pattern so it doesn't overwrite anyone's existing PowerShell profile.

Small piece of automation, but it removed a recurring friction point for the team and kept paying off once we moved into day-two operations.

Outcome

The migration completed successfully across ~1,000 users with no data loss. Users stayed working through cutover. The MFA and Teams rollouts both landed cleanly, which for a project of this size meant hundreds of change-management touchpoints ending without fire drills.

The MFA and Teams rollouts were the two pieces I'm most proud of. Both had the biggest human surface area, and both landed.
