3. What version 2 adds (each makes A1 stricter; none relaxes the authorization)

  - Every row of every output is checked, not only the verdict row. A missing, duplicated, unknown or malformed row, a
    verdict (H99, X99, C99, I99) other than PASS, or a required row whose ok is not true is a STOP at once. The
    required rows are pinned in the runner, so no output can make a required row optional.
  - The rules of sections 1 and 5 that rows carry: H07 must report neondb_owner as the commercial table owner; C01 must
    report PostgreSQL 18; C20 must report neondb_owner, not a superuser; C21 is required (PostgreSQL 17 and later).
  - Identity audit: an impersonated live session, or a live session that is not of a verified user without an
    account row (I07), is a STOP.
  - TLS is sslmode=verify-full on every connection, whatever the service entry says, and the environment variables
    that could redirect the connection or change the session (PGHOST, PGOPTIONS and the like) are cleared.
  - The runner refuses to run without a terminal or in an AI-agent or CI shell, shows the target and both hashes,
    and goes on only when the operator types RUN A1.
  - It refuses to run unless PP_RUNNER_SHA256 equals its own SHA-256 (the value above), records that hash in the
    manifest, keeps a copy of itself and of every file it runs, and writes sha256sums.txt over all of the evidence.
  - It refuses an evidence directory inside the repository or in a folder that may sync to the cloud (Documents,
    Desktop, iCloud Drive, Dropbox, Google Drive, OneDrive).
  - The result is the last line printed and matches the exit code: HOLD 10; STOP 2 (before any connection), 3 (at a
    connection) or 4 (a check failed). Any other nonzero code, an interruption included, is a STOP too.
