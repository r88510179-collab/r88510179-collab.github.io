## Method notes and limits

- ESPN's edge answers `403` without CORS headers to the `HeadlessChrome` user agent, so the browser's direct ESPN request failed and the publishers used their designed fallback, the committed `api/qa-schedule.js` (served locally by `runner/local-server.mjs`, on the preview by Vercel). The browser identity was not disguised.
- The compare-and-swap race (P14) holds one unchanged `PATCH` until a second session publishes; nothing else intercepts traffic. Service workers are blocked in test contexts so every read is fresh.
- Mobile checks use CSS viewports with touch emulation, not physical phones. A temporary Vercel share link for the deployment (created by Vercel's connection-authorized access; expires about 2026-11-06 23:52) was used; its token is not recorded anywhere.
- Residual hazard outside this scope: `admin/rulings-admin.js` on this QA branch still targets the QA parent with the production identity (unchanged here). Do not use Incident Rulings from this branch.
- Synthetic accounts, policies, CORS entry and published QA rows were left in place (no deletion without owner approval).
