# Personal Pool Alerts sender (isolated candidate)
Run on Node 22+ with npm install after dependency review. Requires a persistent Node service with HTTPS reverse proxy. This is not a static GitHub Pages feature and is not deployed yet.
- Create an isolated database and verify target identity, apply schema.sql there only, create least-privilege roles. Grant the sender only the five publication metadata columns, schema usage and necessary alert table rights. Never expose alert storage to the Data API or anonymous role.
- Set DATABASE_URL, EXPECTED_DATABASE, EXPECTED_DATABASE_HOST, NEON_AUTH_URL, NEON_DATA_URL, APP_ORIGIN, VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT, ENROLLMENT_CODE (random 20+ chars), PUSH_ENABLED=true and PORT as protected environment configuration. Do not commit secrets. Generate a dedicated VAPID keypair with web-push. Confirm the DB and public API point to the same isolated environment; use a dedicated DB credential, not production admin.
- Configure TLS, an exact allowed origin, edge rate limits/body size limits, and durable DB backup. The built-in process-local rate limit is a secondary guard, not a substitute for edge protection. Do not trust unvalidated forwarded IP headers.
- Initial tick establishes baseline without sending old releases. Every 30 seconds it compares the committed latest locked identity with the anonymous public read. Only the latest season/week is watched; historical corrections are intentionally not broadcast. A rapid sequence between polls can coalesce revisions; no claim of exactly-once network delivery. Stable per-revision notification tags mitigate duplicate display after crash/retry.
- Delivery pauses if public reads fail. The current locked row is rechecked before sending, and queued older revisions are cancelled when a newer verified release arrives. Test withdrawal and re-publication in the isolated environment before enabling production. Test subscription revocation and in-flight delivery races: a push already handed to a provider cannot be recalled.
- No emails or participant picks are included in push payloads. No live deployment until integration tests, endpoint allowlist validation, mobile acceptance, database fingerprint and owner release authorization.
